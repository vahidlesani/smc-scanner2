## ۱) کد رنگ نقاشی دستی ویوا (قانون ثابت خوانش چارت‌ها)

| رنگ/ابزار دست ویوا | معنی |
|---|---|
| **خط آبی (کشیده با انگشتی/دراو)** | **ورود (ENTRY)** |
| **خط قرمز پررنگ** | **استاپ (STOP)** |
| **خطوط سبز افقی** | **تی‌پی‌ها (TP1/TP2/TP3)** |
| **باکس قرمز کم‌رنگ (نیمه‌شفاف)** | **زون عرضه (SUPPLY) — باید توسط انجین رسم شود** |
| **خط ترند قرمز دستی** | ترندلاین منتخب — انجین باید همان بهترین خط را انتخاب و رسم کند |
| **مستطیل بنفش/سفید بزرگ دستی** | بیس/زون تقاضا — باید به‌صورت مستطیل رسم شود |

## ۲) قوانین رندر (از همین اسکرین‌شات‌ها — صف اجرا)

1. «در همهٔ ستاپ‌ها این باکس‌های عرضه **قرمز** باشند.» — زون عرضه = باکس قرمز کم‌رنگ، همه‌جا.
2. باکس فقط وقتی رسم شود که **فاصله/عرض معنادار** دارد («تفاضای بیشتر اگر وجود داره رسم بشه»).
3. HBAR: بیسِ تقاضای بزرگ باید **مستطیل** رسم می‌شد (باکس دستی ویوا مرجع است).
4. SUI 15m: خطوط **خیلی شلوغ** شد (۳ خط قرمز موازی + فیروزه‌ای + آبی) — **بهترین ترندلاین انتخاب شود**، بقیه حذف (قانون DECLUTTER: یک والد هر سمت).
5. ADA 30m: کندل‌ها کمی کوتاه‌تر/پایین‌تر تا **دو پیکان ترند روی هم نیفتند** (تداخل لیبل/فلش).
6. ARB FINAL-WATCH→CONFIRMED: ترندِ قرمزِ دستی ویوا (شیب‌دار از سقف 0.233) همان است که انجین باید رسم کند + باکس supply کم‌رنگ بالا.

## ۳) تفاوت TECHCLASSIC و TLBREAK (قانون ویوا — verbatim)

> «فقط یک تفاوت بین تکنوکلاسیک و TLBREAK هست: **TLBREAK می‌تواند در ریجکت‌ها به نواحی هم سیگنال تأیید بکند** — یعنی اصلاح‌های ضد روند اصلی — آن‌هم با **موتور متوهم هوشمند (TOHOM)** که موقعیت پوزیشن از بین نره.»

- **TECHCLASSIC = فقط هم‌روند:** روند نزولی که رو به بالا شکست → LONG؛ روند صعودی که رو به پایین شکست → SHORT؛ الگوها همین‌طور (شکست بالای الگو → LONG، پایین → SHORT). ورود = کلوزِ بعد از شکست یا تأیید هوشمندِ پیش از کلوز. زون‌ها (flip/limits/FVG/OB) **فقط امتیاز**، هرگز وتو.
- **TLBREAK = همان قوانین + لاینِ اضافهٔ ضدروند:** دفع/ریجکت در نواحی خلاف روندِ والد مجاز است، با تأیید TOHOM/توهم هوشمند تا پوزیشن از دست نرود.
- شخصی‌سازی TLBREAK: راند بعدی (جدا).

## ۵) کالیبراسیون r60 (اعمال‌شده — فقط TECHCLASSIC)

1. **وتوی چندتایم‌افریمی برداشته شد:** برای BREAK تکنوکلاسیک، روندِ عقب‌ماندهٔ والد دیگر `COUNTER_TREND_TOUCH_ONLY` نمی‌دهد — فقط هشدارِ ثبت‌شده در متادیتا (`mtf_context_warning_tc`).
2. `htf_alignment` از گیت‌های اجباریِ BREAK حذف شد (فقط امتیاز/متنEvidence). FADE ها همان اجبار را نگه دارند (فقط‌هم‌روند).
3. قفل جهت با قرارداد `break_direction` (UP→فقط LONG، DOWN→فقط SHORT) — همان قرارداد TLBREAK؛ حالا در چکِ قرارداد صریح است.
4. رفتار TLBREAK/PINVAL/بقیه: **دست نخورده** (تست‌های حفاظ موجودند).
5. **باقی‌مانده (فهرست بعدی):** باگ D دریفتِ پروجکشن خطوط (ARB دو بار کشف شد؛ INSIDE_PATTERN/BREAK_SIDE ممکن است کلوز معتبر را کاذب رد کند)؛ ترجیح ورود پولبکی (ADA: خط آبی ویوا پایین‌تر از ورود انجین بود)؛ رندرهای بند ۲.
