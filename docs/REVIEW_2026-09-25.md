### B1 · مهم‌ترین مشکل: هیچ سنجش آماری روی ۵ ستاپ فعال وجود ندارد
بک‌تست موجود (`analysis/backtest.py`) مال ستاپ‌های core v7 است که خاموش‌اند. P1234 و TLBREAK قدیمی با IS/OOS سنجیده شدند، اما TECHCLASSIC، ALBROX، PINWALLQ و PINVAL **فعلی** با قوانین راند ۱۱ تا ۳۱ هیچ عدد expectancy ندارند. هر «قانون» جدید فقط با چند چارت نمونه تنظیم شده است.
**پیشنهاد (بیشترین اثر روی کیفیت):** یک replay walk-forward که **همان** `scan_setups` → `evaluate_confirmation` → `build_ladder/advance_ladder` لایو را روی دیتای تاریخی اجرا کند:

```python
# experiments/replay_live_setups.py  (اسکلت)
for t in walk_forward_times(start, end, step=trigger_tf):
    bundle = slice_bundle(full_frames, until=t)            # فقط کندل‌های بسته تا t
    for cand in scan_setups(bundle, style):
        open_candidates.append(cand)
    for cand in list(open_candidates):
        ok, cand, _ = evaluate_confirmation(cand, frames_after(cand, t), None)
        if ok:
            trades.append(simulate_ladder(cand, full_frames, fee=0.055, slip=0.02))
            open_candidates.remove(cand)
report(trades, by=["setup_code", "trigger_timeframe", "direction"],
       metrics=["n", "win_rate", "avg_R_net", "profit_factor", "max_dd"], split="IS70/OOS30")
```
هر قانون جدید فقط وقتی merge شود که avg_R_net در OOS بدتر نشده باشد.

### B3 · clamp استاپ با دکترین «استاپ پشت سوینگ» در تضاد است
`clamp_stop_price` استاپ ساختاری دور را روی ۱٫۲۵ تا ۸٪ **می‌بُرد**. نقطهٔ جدید دیگر پشت هیچ ساختاری نیست و فقط یک عدد درصدی است، یعنی همان «استاپ هانت‌شدنی» که خودتان گزارش داده بودید. دو گزینهٔ سالم‌تر:
1. `STOP_CEILING_MODE=reject`: ستاپ آموزشی بماند و اجرایی نشود.
2. `STOP_CEILING_MODE=limit_entry`: ورود لیمیت نزدیک‌تر به ساختار (مثل `pinwall_entry2`) طوری که فاصلهٔ ورود تا استاپ ساختاری داخل سقف قرار بگیرد.
```python
mode = os.getenv("STOP_CEILING_MODE", "clamp")
if _q_clamped and mode == "reject":
    return reject("STOP_BEYOND_CEILING", "استاپ ساختاری بیرون از سقف تایم‌فریم است.")
if _q_clamped and mode == "limit_entry":
    lim = sl_struct + (1 if long else -1) * entry * ceiling_pct / 100
    candidate.metadata["limit_entry"] = lim   # ورود فقط با لمس lim
```

## بخش C — سلامت کد (ریشهٔ «هر روز بدتر شدن»)
1. `evaluate_confirmation` حدود **۹۰۰ خط** در یک تابع است با ۱۵+ مسیر reject و state mutation. پیشنهاد: pipeline از گیت‌های کوچک `(candidate, ctx) -> GateResult` که هرکدام تست مستقل دارند و ترتیبشان در یک لیست تعریف شده است.
2. ۵۱۳ مورد `except Exception` در کد runtime که ۱۵۳ تای آن‌ها فقط `pass`/`continue` است (در ممیزی ۰۹-۱۴ این عدد ۲۱۸ بود). حداقل کار: یک شمارندهٔ سراسری `SWALLOWED[site] += 1` که در heartbeat لاگ شود. باگ‌های A1 (در tz-aware)، A6 و A7 همه همین‌جا گم شده بودند.
3. کامنت‌ها با اعداد جدول‌ها تناقض دارند. مثلاً docstring `clamp_stop_price` می‌گوید «1h 1.75%» ولی جدول ۲٫۷۵٪ است. کامنت‌ها را به ارجاع به جدول تبدیل کنید، نه تکرار عدد.
4. `CHAT_CONTEXT.md` طبق خود HANDOFF منسوخ است. حذف یا آرشیوش جلوی گمراه‌شدن ایجنت‌های بعدی را می‌گیرد.
